# 公司档案研究：范围 → 检索 → 阅读 → 主题/行业/公司三层写作 → 自检 → 交付 → 复盘

本文件与具体 AI 平台无关。能读文件、运行代码的智能体照此执行；只能对话的 AI 用同目录的 `PROMPT.md`。
模板在 `templates/`；研报库检索脚本复用上级目录的 `../scripts/`（`library_search.py`、`prepare_reading.py`、`pdf_text.py`）；出处规则、协作规范与 `../SKILL.md`（sellside-valuation-audit）一致。

## 与 sellside-valuation-audit 的分工
| | company-dossier（本文件） | sellside-valuation-audit |
|---|---|---|
| 回答 | 这是一家什么样的公司、它怎么走到今天、往前看最大的问题是什么 | 这家公司值多少钱、券商的模型对不对 |
| 产出 | 公司档案报告（+ 行业报告、主题报告） | 估值模型 + 估值报告 + 核查 |
| 未来部分 | 只给方向和量级 | 情景、概率加权、反向推算 |
| 停止点 | **没有**，全程自动 | A3 讨论检查点 |
用户要"研究一下 XX""给我一份 XX 的完整研报""帮我搞懂 XX" → 用本文件。
用户要"XX 值多少钱""核查这个模型" → 用 sellside-valuation-audit。
两者都要 → 先本文件，再把档案报告作为输入交给 sellside-valuation-audit。

## 合格标准
读者是用户本人，一份合格的公司报告读完（约 30 分钟）应能回答六个问题：
1. 这家公司怎么走到今天，遇到过哪些生死关头或转折点，当时怎么选、结果如何
2. 现在谁在管它，这些人的时间和精力花在哪
3. 过去十年股价为什么大起大落，市场当时的解读事后看对不对
4. 相对它自己的历史，现在贵不贵；现价大致隐含什么样的预期
5. 往前看最大的几个问题是什么、各自可能性和量级；以它过去解决问题的记录判断，能不能过关
6. 它在行业里什么位置，同行里谁强谁弱、为什么

## 核心原则
1. **历史数字必有出处。** 每个历史数字标"[R编号 p页]"或"[S编号 p页]"；数据来源（股价、倍数）写明提供方和取数日期。
2. **禁止点预测。** 不写目标价，不写某年的营收或 EPS 数字，不做概率加权。未来只允许三类表达：可能性（高 / 中 / 低）、影响量级（大：足以改变估值区间 / 中 / 小）、方向（偏乐观 / 中性 / 偏悲观）。券商目标价可以作为"市场预期"的证据被引用，但不能作为本报告的结论。
3. **历史优先于预测。** 公司报告篇幅分配：历史 + 团队 + 股价事件 ≥ 50%，估值 ≤ 15%，未来 ≤ 25%，行业位置 ≤ 10%。
4. **事后评判要公平。** 评价市场当时的解读，只用当时能看到的信息；"市场当时怎么想"必须引用事件前后两周的研报或当时的报道，不能用事后文章。
5. **猜测与结论分开；争议写两面。** 两种解读都说得通时并列写出，不替用户选。
6. **必须联网。** 历史、团队、股价事件三节依赖公开资料（见"来源分工"）。无法联网时停止并告知用户，不要用记忆凑数。
7. **研报原文不外传。** 不把研报原文或大段摘录放进公开位置；交付时提醒使用条款。
8. **不停下。** 范围、行业划分、历史节点的取舍、事件门槛的调整，全部由 AI 自行决定，并在报告末尾"本报告的取舍"一节逐条列出理由。立项仍由用户决定，产出写进收件箱。

## 三层结构
| 层 | 回答什么 | 何时写 | 篇幅 |
|---|---|---|---|
| **主题** | 贯穿多个行业的共同驱动力（一轮资本开支周期、一项监管、一种技术替代、一次宏观冲击）：钱从哪来到哪去、历史上类似周期怎么开始怎么结束、谁受益谁受损 | 请求涉及 ≥ 2 个行业且存在共同驱动力；或用户点名 | 4–6 页 |
| **行业** | 价值链与利润池、份额变迁（近 10 年）、周期位置、横向比较表、行业共同的利好利空、各公司在行业中的位置 | 每个被研究公司的主行业各一篇；库里已有且 ≤ 90 天的可直接引用 | 6–10 页 |
| **公司** | 五节正文 + 行业位置 + 取舍 + 来源（见模板） | 每家一篇 | 8–12 页 |

**顺序固定：主题 → 行业 → 公司。** 后一层引用前一层，不重写。公司报告里的"行业位置"只保留 1–2 页，指向行业报告。
单家公司的请求：D0 判定所属行业后，先查研究总库 `30 研究主题/` 和 `00 收件箱/` 有没有 90 天内的该行业报告；有就引用，没有就先写一篇精简版（4–6 页）再写公司。
一家公司横跨多个行业（如同时做云和广告）：以收入或利润占比最大的为主行业，其余行业在"行业位置"一节各写一段。

## 来源分工
| 报告部分 | 主要来源 | 研报库的角色 |
|---|---|---|
| 公司历史 | 10-K 的业务与风险章节（逐年回看）、公司官方历史、权威传记与长篇报道、当年的财报电话会 | 当年的研报：看当时卖方怎么评价那次转折 |
| 团队 | 代理声明（DEF 14A：高管名单、任期、薪酬结构、持股）、近 12 个月 Form 4、CEO 公开发言与访谈、董事会公告 | 基本帮不上；偶有管理层会议纪要 |
| 股价事件 | 日线数据（写明提供方）、事件当日的公告或新闻 | **核心用途**：事件前后各 14 天的该公司研报 = 当时的市场解读 |
| 历史估值 | 可靠的数据提供方（写明），或从财报自行计算 | 研报中的历史倍数图可作交叉验证 |
| 未来利好利空 | 最近两次财报电话会的问答、10-K 风险因素、监管与诉讼文件 | 最近 3 个月研报：标注每条利好利空"谁支持、谁反对" |
| 行业与主题 | 行业协会与政府统计、龙头公司财报中的行业数据 | 库里"行业 / 策略 / 主题 / 宏观"类报告是主要素材 |

**研报库怎么检索：先读研报库根目录的说明文件（如 `00_先读我_研报库说明.md`），按它写的目录结构与字段检索。** 本文件不规定列名和路径，库结构变了以说明文件为准。能运行代码时用 `../scripts/library_search.py`（按代码、公司名、行业关键词、`--since`）；检索股价事件窗口时按日期范围筛。

## 流程

### D0 范围判定（不等用户）
1. 列出映射表：公司 → 主行业（及次行业）→ 共同主题（有则写，没有写"无"）。
2. 判定要写哪几层、各几篇；检查库里已有的行业 / 主题报告能否复用。
3. 用一句话向用户报告范围和预计产出，**不等回复**，直接继续。

### D1 检索
- 研报库：公司类（按代码、公司名，近 24 个月）；行业 / 策略 / 主题类（按关键词，近 12 个月）；股价事件窗口（每个事件 ±14 天）。入选一般 10–30 份，太多时按机构取最新 + 观点转折的节点。
- 公开资料：按"来源分工"逐项取。每份来源在 `01_来源/来源清单.csv` 登记 S 编号。
- 股价数据：取近 10 年日线，计算单日涨跌幅和滚动 21 日涨跌幅，按默认门槛筛出事件清单，写入 `event_ledger.csv`。

### D2 阅读
- 阅读包沿用 `../templates/reading_pack.md`：每份研报一张摘要卡，加各家观点对比、分歧地图、数据时间线。
- 新增两张台账：`templates/milestone_ledger.csv`（历史节点）、`templates/event_ledger.csv`（股价事件）。每行一个出处。
- 出处台账沿用 `../templates/claim_ledger.csv`。

### D3 写作
按模板写，顺序主题 → 行业 → 公司。每写完一层就交付那一层（见 D5），不要攒到最后。
- 主题：`templates/theme_report.md`
- 行业：`templates/industry_report.md`
- 公司：`templates/company_report.md`

### D4 自检（五问，逐篇做）
1. 每个历史数字都有出处吗？没有的删掉或标"待核实"。
2. 有没有任何一处写了未来的精确数字（目标价、某年 EPS、概率百分数）？有就改成方向和量级。
3. 公司报告第五节最后一段，有没有真的引用第一节的具体案例来判断"能不能解决"？
4. 股价事件的"市场当时解读"引用的是不是事件 ±14 天内的材料？
5. 公司报告"行业位置"里的份额、增速，与行业报告的数字一致吗？
再做一次篇幅检查：五节比例是否符合核心原则第 3 条。

### D5 交付
- 位置：研究总库 `00 收件箱/<AI名>/<日期>_<范围简称>/`，分 `主题/`、`行业/`、`公司/` 三个子目录；有立项的项目写进 `05_成果/`（文件名以 `草稿_` 开头）。
- 文件名：`YYYYMMDD_<代码或行业名>_公司档案_v1_<AI名>.md` 及同名 `.docx`；图表 PNG 同名加 `_fig1` 等。
- 每篇报告正文前放一张"一页摘要"：六个合格标准问题各一两句回答。
- 收尾：按协作规范在 `06_协作/交接日志.md` 追加一条，更新任务板。
- 交付说明：几句话写结论、本报告的主要取舍、哪些来源待核。

### D6 交叉审核（有条件时做）
另开一个会话（可以是不同模型），按 `../SKILL.md` 模式 B 的 B4 核对出处，重点核：历史节点的时间与数字、股价事件的当日涨跌幅、团队表中的任期与持股。结论写进 `06_协作/审核记录.md`。审核者与制作者不能是同一会话。

### D7 复盘
沿用 `../templates/retro.md` 与 `../LESSONS.md` 机制：问题、根因、对本文件的修改建议，写入待处理区；用户确认后再改本文件。

## 默认口径（AI 自行套用，不询问）
| 事项 | 默认 | 可调整的情形（调整后写进"取舍"） |
|---|---|---|
| 历史节点数 | 成立至今 5–8 个，优先"几乎死掉"或"改变业务结构"的时刻 | 成立不足 10 年的公司 3–5 个 |
| 股价事件门槛 | 近 10 年，单日 ±8% 或滚动 21 日 ±20% | 事件超过 15 个时提高门槛；小市值放宽到 ±12% / ±30% |
| 宏观性事件 | 与大盘同向且幅度相近的事件标"宏观"，只列表不展开 | — |
| 历史估值指标 | 近 10 年 P/E（动态）、EV/EBITDA、FCF 收益率 | 金融股换 P/B + ROE；无利润公司换 EV/Sales；REIT 换 P/FFO |
| 利好 / 利空条数 | 各 3–6 条，按"可能性 × 量级"排序 | — |
| 行业横向比较对象 | 3–6 家，含被研究的公司和份额最大的同行 | — |
| 行业报告有效期 | 90 天内可引用；过期至少更新份额和近况 | — |
| 时间口径 | 以报告日为准；财年与日历年差异在表头注明 | — |
| 篇幅 | 公司 8–12 页，行业 6–10 页，主题 4–6 页（Word 页） | 用户另有要求 |
| 格式 | `.md` 源稿 + `.docx`；公司报告 2–4 张图：历史估值带状图、股价事件标注图、份额或收入结构变迁图 | — |

## 公司报告五节（详见 `templates/company_report.md`）
**一、历史：关键节点与应对。** 每个节点一张卡：时间 ｜ 遇到的问题 ｜ 当时的选择（和没选的路）｜ 结果 ｜ 这说明了什么。结尾一段：这家公司解决问题的"习惯"（靠什么过关：技术、收购、换人、烧钱、政策）。
**二、团队。** 创始人状态（在 / 不在 / 以何身份在、持股变化）；CEO 与核心高管表（姓名、职位、任期、背景、持股、其他职务）；时间精力去向（近 12 个月公开发言主题分布、兼任、接班安排）；薪酬结构指向什么目标；近 12 个月内部人买卖。
**三、股价重大事件。** 事件表 + 每个事件一段：发生了什么 ｜ 市场当时解读（引当时研报）｜ 事后看 ｜ 教训。结尾一段：市场对这家公司惯性误判的方向（总是高估什么、低估什么）。
**四、估值：历史区间。** 区间表与带状图；高点、低点各对应什么环境；当前分位；现价隐含预期的定性判断；与同行比贵还是便宜、为什么。
**五、未来：利好与利空。** 利好表、利空表（是什么 ｜ 为什么重要 ｜ 可能性 ｜ 量级 ｜ 谁支持 / 谁反对 [R编号]）；乐观叙事、悲观叙事各一段；**最大的一个问题是什么，用第一节的具体案例判断它能不能解决。**
**附：行业位置**（1–2 页，引用行业报告）；**本报告的取舍**（AI 做了哪些决定、为什么）；**来源**（研报 R 编号 + 公开资料 S 编号 + 数据提供方与取数日期）。

## 常见陷阱
- 公司官方历史会淡化失败和被迫的选择；每个节点至少一个第三方来源交叉。
- "创始人仍在"不等于"创始人仍在管"：看职务、董事会角色、持股变化、近一年公开露面。
- 单日大涨跌可能是宏观或指数事件（加息、指数调仓、板块轮动），不是公司事件；要区分并标注。
- 估值倍数跨越会计或口径变化（租赁准则、SBC 处理、分拆合并）时不可比，注明。
- 卖方研报在事件后一周内常集中改评级，"当时解读"取事件前的研报 + 事件后 3 天内的首次反应，不取两周后的回顾。
- 行业份额数据各家口径不同（出货量 / 收入 / 装机），同一张表只用一种口径。
- 把券商目标价写进"未来"一节当结论，是最常见的违反第 2 条的方式。

## 输出风格
与用户语言一致；金额用"亿美元"（或对应币种）；结论先行；对照用表格；正文用短句；每条结论附来源。不构成投资建议；陈述券商原文和方法，不臆测动机，提示其披露的利益冲突。
