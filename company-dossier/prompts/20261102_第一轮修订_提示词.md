## 通用提示词

```
用 company-dossier skill 的"模式 R：修订已交付的报告"，把下面这篇第一轮报告升级到当前版本（GitHub Bill-Zzz/-SOP，company-dossier 0.7.0；没装 skill 的先读仓库里的 company-dossier/SKILL.md 和 PROMPT.md）。

总原则：
1. 不重做研究。v1 本身就是既有研究，正文判断和已有数字默认沿用；只在三种情况回原始出处查：数字过时（更新到最新一季）、与 Excel 或其他来源矛盾、正文核心论点要靠它撑。
2. 只做四件事：改结构、补账、改呈现、补留档。

【公司报告】
- 先建历史数据 Excel：从 Google Drive「计算机 › 我的 Mac › futu_export/<代码>/」取长表、日线、底稿CSV，从 GitHub 取 company-dossier/scripts/build_history_xlsx.py 运行，--check 须通过；不能运行代码就手工建年度三表、年度衍生指标、近12季度明细、市值与估值四张表。
- 结构改为七节：一 历史 → 二 财务全史 → 三 行业位置与竞争 → 四 团队 → 五 股价重大事件 → 六 估值 → 七 未来。
  · 二 财务全史为新写：全史总表、增长分解、钱去哪了、说到做到、盈利质量、近12季度趋势，数字全部取自 Excel。
  · 三 行业位置与竞争：把原附录扩写为正文，写份额趋势、主要竞争对手逐家一段（在哪正面竞争、谁在赢、依据什么数字）、强项弱项各配数字、它独有的问题；数字引用行业报告。
  · 第一节每个历史节点的"结果"补上 Excel 里对应年份的数字；第七节最后一段改为用第一节案例、第二节数字、第三节竞争位置来判断最大的问题能否解决。
- 历史、财务、估值三节的数字逐个与 Excel 核对，不一致以 Excel 为准，改动连同原值记入修订说明表。
- 图表补到 ≥10 张：财务 ≥5、竞争 ≥2、股价事件 1、估值 ≥2。原生图表放 Excel"图表总览"，文档里放快照，图下注"数据与可编辑图表：<Excel 文件名> 图表总览第 X 图"。

【行业 / 主题报告】
- 结构不动。半导体相关的行业报告，"周期与现状"一节改为引用半导体周期主题报告的判断。
- 横向比较表、份额表里的公司数字，有公司 Excel 的就对一遍；没有的跳过，不为此新建 Excel。
- 图表补到行业 ≥5 张、主题 ≥3 张。

【所有报告：排版规范】
- 表格一律做成真表格，不用图片；单元格一项一行，来源编号单独一列；不同维度的标签写在同一行，用"·"并列。
- 每组重要数字，正文至少一处写明分子÷分母、样本、时点、单位；份额、利润率、利润池占比要分清。
- 正文去括号：单位、时间、增速写进句子，来源用方括号放句末；只有公式保留圆括号。
- .docx：说明性段落用正文样式，表注、图注、来源用 9pt 深灰。

【交付】
- 存为 v2：文件名序号 v1→v2，AI 名换成你自己的；正文开头放"修订说明"表（位置｜原版｜修订｜结论是否改变）。v2 写在 v1 同目录；v1 能移入同目录"历史/"就移，不能就原地保留，不删除、不覆盖。
- 公司报告的 Excel 与 v2 放同一目录。
- 按 skill'留档：复用与复核'：在本批成品目录写 `留痕/<篇名或代码>/复用/`（把 v1 过程产物整理进去：Excel、来源清单、数字台账含核心列、研报摘要卡、历史节点、股价事件、来源副本、结论卡）和 `复核/`（自检.md）。差不多齐全即可。
- 交接日志追加一条，写明 v2 和 `留痕/<篇名或代码>/` 的路径、结论是否改变。
- 全程不停下来问我；需要取舍的地方写进"本报告的取舍"。
```
