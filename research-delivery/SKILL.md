# 研究报告格式与交付（research-delivery）

本技能只管把写好的内容做成合规交付物，不管研究和写作。执行者不读 research-sop 的 SKILL.md；要用的规范和脚本都列在下面。

仓库：GitHub Bill-Zzz/-SOP，下文路径都相对仓库根目录；不能克隆时取 `https://raw.githubusercontent.com/Bill-Zzz/-SOP/main/<路径>`。依赖 `pip install python-docx openpyxl matplotlib`；改已有工作簿要 LibreOffice。版本随仓库 `VERSION`。

## 铁律
1. 不改内容：数字、句子的意思、结论、章节名与顺序、图注里的结论句都不动。
2. 只改版式：标题编号与全角空格、表头单位写法、表格拆分与列宽、图号顺序与图片文件名、图下来源行与"数据与可编辑图表"行的写法、字体字号行距颜色、目录、页眉页脚、文件命名与位置。
3. 脚本报出的内容类问题不自己改，写进打回单；格式类问题自己改到通过。
4. 不删除、不覆盖 Drive 上已有文件；新版本另存。

## 收到什么
任务文件夹里的 `交接单.md`（模板 `research-delivery/交接单模板.md`）：每篇的报告 .md、图片目录、数据表、底稿、要新画的图、Drive 任务文件夹、本轮特殊要求、交付说明。缺件先报，不猜。交接单里"数字比对"不是 0 的，整篇打回。

## 步骤

### C1 报告转换
- `python3 research-sop/scripts/md2docx.py <报告>.md --out <报告>.docx --img-root <图片目录>`；只检查用 `--check-only`。不用 docx 技能重写报告；只有交接单写明"保留修订痕迹"的修订版，才用 docx 技能在原文件上改。
- "格式检查""标题编号""表头单位""图号与文件名""图下来源行"：改 .md 的版式，直到格式检查全部通过、各项 0 处问题。
- "报告外壳"：板块顺序不对的只移动板块、不改内容，移动后目录与交叉引用跟着改；缺"一页摘要""结论""概述"，或取舍、来源、修订说明写在正文，打回。
- "出处标注与过程用语"：正文的 `[R… p…]`、`[S…]`，数字台账里已有同一数字、同一出处的直接删标注，否则打回；"研报库""台账""对账""取证"等过程用语打回。
- "图表优先"提示（数字墙、数值大表、没有图的正文章）打回，由写的人改图或删减。
- 图片缺失：先在交接单给的目录找；"要新画的图"按 C3 画；仍缺的打回。

### C2 表格排版（改 .md 里的表格）
- 一格一个项目；不同维度的标签写同一行（"前道 · 代工"）；超过 3 项的名单分行或拆列。
- 表头写单位和时点；单位或时点原文没有的打回，不猜。
- 宽表先调列宽、换行，仍放不下就竖版分表并重复表头；不缩字号。

### C3 图表与图表工作簿
- 图片按图号复制为 `figN_<描述>.png`，N 与图注一致，图内不写图号。
- 交接单"要新画的图"：在该篇图表工作簿（历史数据表或图表数据表）里建原生图，导出 png 插回 .md；数据只取交接单写明的工作表与列，取不到打回。
- 工作簿结构按格式规范第 13.1 节 WB01–WB06；首页"图表总览"与"图表计算"按 Excel 规范，走复制母版或 Sheets API，不经 openpyxl → xlsx；建页断言不过即中止，按输出改到过。
- 图表可读性（所有图）：
  - 横轴用文本类别（"YYYY-MM"或"YYYY-MM-DD"字符串），不用日期轴。
  - 每张图最多 3 个系列（图表总览交互图按 Excel 规范 2.5）；不用隐藏系列、数据标签技巧、空心标记。
  - 折线无标记点、不平滑。
  - 要标注的日期和数字放图旁小表；日数据超过约 500 点改用月末数据并在图下注明。
  - 至少在一个非 Excel 查看器（Google 表格或 LibreOffice）里看一遍：图例项数对、横轴可读、柱和线可见。
- 图号、图注、来源行、色板按格式规范第 7 节；平台支持原生图表时交数据行，不贴图片。
- 改已有工作簿走 `scripts/xlsx_patch.py` → `scripts/lo_recalc.sh` → `scripts/xlsx_diff.py`，不用 openpyxl 保存已有工作簿。

### C4 上传与转换
- Drive 上的报告一律 Google 文档、表格一律 Google 表格；png 与原始来源副本保留原格式。本地 .md、.docx、.xlsx、.csv 是中间件，上传时转换（mimeType `application/vnd.google-apps.document` / `application/vnd.google-apps.spreadsheet`），不上传原件。底稿里的结论卡、取舍、复核记录、修订说明转 Google 文档，台账、来源清单等 csv 转 Google 表格。
- 位置按 Drive 根目录入口文件的"工作区任务文件夹布局与交付清单"；命名按存储规范，如 `AAPL_历史数据_20261104_V1.0`，本地中间件名上传时改。不自写目录结构，不排除规范要求的文件。
- 通道：有 rclone 或 Drive API 二进制通道就自己传；Drive MCP `create_file` 只适合约 9 KB 以内的文件；没有通道就把成品交给用户，写明"上传时选择转换为 Google 文档 / Google 表格"。不手写 base64。
- 修订版：文件名版本号加一（`_V1.0` → `_V2.0`），旧版不删。
- 丢图的工作簿按"图表计算"在 Google 表格里重建，在"说明"页记一行。

### C5 转换后修补
按转换后修补清单：D1 目录页码必做，补好前不算交付；D2、D3、S1–S3 照做；API 写不了的（图表刻度字号、网格线颜色）列进回报请用户补。

### C6 交付核对
`python3 research-sop/scripts/check_delivery.py --drive "<任务文件夹 rclone 路径>"`（参数见脚本开头），不通过按输出改到通过。读不到文档文本时用 `--toc-evidence` 附人工确认。不能跑脚本时按入口文件摆放命名，目录页码附导出 PDF 目录页或截图。

### C7 索引
按 Drive 研究库 `00_索引` 的「说明」页更新：交付报告或数据表时「产出」每个文件加一行，同对象同类型旧版本"是否最新"改否、状态改旧版；「进度」该对象改待审、更新日期改当天。修订版同样处理。只加行、改状态列，不删行。

## 打回
- 写 `<任务文件夹>/打回单.md`，一行一条：`篇 ｜ 位置（章节）｜ 原文 ｜ 问题 ｜ 脚本输出那一行`。
- 写的人改完后，只重跑相关脚本、只核对改过的位置，不重做全篇。

## 回报（不超过 10 行）
文件清单与 Drive 链接；`check_delivery.py` 最后一行；打回单条数与路径；请用户补的项；交接单里的"交付说明"原样附后。不贴脚本原始输出。
