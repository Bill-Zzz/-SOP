# Research SOP：主题·行业·公司（research-sop）

本技能只管怎么研究、怎么写；用 Google Drive 时按 Drive 里的规则做。

流程：范围 → 取数建表（工单 A）→ 检索与阅读 → 写作 → 数字比对 → 数字抽查（工单 B）→ 格式与交付（research-delivery）→ 复盘。

版本：0.22.0。版本记录见 CHANGELOG.md。

只能对话的 AI 直接粘贴本文件。章节、篇幅、图表分配见题型模板 `../research-prompt/templates/题型_*.md`，任务书另定的以任务书为准。出处记法（R / S 编号与页码）同 `../SKILL.md`，只记在底稿。

## 分工：判断与机械
本文件只写执行者本人要做的判断与写作。机械活写成工单，每轮按分档自己做或派出去：

| 工单 | 文件 | 默认执行者 |
|---|---|---|
| A 取数建表 | `工单/工单A_取数建表.md` | Opus 中推理子 Agent |
| B 数字抽查 | `工单/工单B_数字抽查.md` | Opus 低推理子 Agent |
| C 格式与交付 | `../research-delivery/SKILL.md` | Opus 中推理子 Agent，可改 Sonnet 或 Codex |
| D 入库 | research-library 技能 | Sonnet 子 Agent |

- 分档写在任务书"已定设计"或派活那句话里（"本轮格式自己做""C 用 Codex"），没写按上表。
- 派出去的工单只给文件路径，回复只要摘要与打回单；派单规矩见 gowork。
- 自己做某张工单时才读那张工单和它列的规范；没让自己做的，不读 `standards/`、工单与 research-delivery。
- 工单打回的，只改打回单上的位置，不重写整篇。

## 与 sellside-valuation-audit 的分工
- 本技能：主题、行业、公司是怎么回事，未来只给方向和量级，全程不停。
- sellside-valuation-audit：值多少钱、核查模型，有 A3 停止点；两者都要时先本技能，再把报告交给它。

## 核心原则
1. **历史数字必有出处，正文不标。** 历史数据表里的数由 `scripts/check_numbers.py` 对上；表外的数（研报、公开资料、既有研究、计算所得、口径常数）写时在底稿 `数字台账.csv` 记一行出处。正文只可写数据提供方的名字（股价、倍数等）。引用 Drive 上的既有研究时，记下其 Drive 文件路径、类型标"既有研究"即算有出处，见"既有研究优先、少重复核对"。
2. **禁止点预测。** 不写目标价，不写某年的营收或 EPS 数字，不做概率加权。未来只允许三类表达：可能性（高 / 中 / 低）、影响量级（大：足以改变估值区间 / 中 / 小）、方向（偏乐观 / 中性 / 偏悲观）。券商目标价可以作为"市场预期"的证据被引用，但不能作为本报告的结论。
3. **历史优先于预测。** 公司报告篇幅分配：历史 + 财务全史 + 行业位置与竞争 + 团队 + 股价事件 ≥ 70%，估值 ≤ 10%，未来 ≤ 20%。
3a. **先把账看完，再写历史。** 每家公司先由工单 A 建一份"历史数据 Excel"（三表、衍生指标、市值与估值、股价事件，时间跨度尽量长），报告的历史、财务全史、团队、估值四节的每个数字都必须能在这份 Excel 里找到。没有这份 Excel 不开始写报告。三表数据**不从 SEC 逐份取**：优先用本地数据导出（如富途导出与底稿），其次券商模型里的历史表；SEC 文件只用于三表之外的东西——分部数据、MD&A 文字、融资与收购、代理声明。
4. **事后评判要公平。** 评价市场当时的解读，只用当时能看到的信息；"市场当时怎么想"必须引用事件前后两周的研报或当时的报道，不能用事后文章。
5. **猜测与结论分开；争议写两面。** 两种解读都说得通时并列写出，不替用户选。
6. **必须联网。** 历史、团队、股价事件三节依赖公开资料（见"来源分工"）。无法联网时停止并告知用户，不要用记忆凑数。
7. **研报原文不外传。** 不把研报原文或大段摘录放进公开位置；交付时提醒使用条款。
8. **不停下。** 范围、行业划分、历史节点的取舍、事件门槛的调整，全部由 AI 自行决定，并在底稿 `取舍.md` 逐条列出理由，不进正文。立项仍由用户决定。

## 三层结构
- 主题、行业、公司三层，何时写、写什么见题型模板。
- 顺序固定：主题 → 行业 → 公司。只要上层时只交付上层；要公司层时下层引用上层，不重写。同一批次多家公司共用的主题报告在批次开头写一次。
- 单家公司请求：先查 90 天内的该行业报告，有就引用，没有就先写精简版（4–6 页）。
- 一家公司横跨多个行业：收入或利润占比最大的为主行业，其余在"行业位置与竞争"各写一段。

## 来源分工
| 报告部分 | 主要来源 | 研报库的角色 |
|---|---|---|
| 全部（最先看） | Drive 上的既有研究 | — |
| 财务全史、分部、融资、收购、IPO | 本地数据导出，其次券商模型历史表、IR 数据包、10-K 分部附注 | 首次覆盖报告与券商模型的长历史表 |
| 公司历史 | 历史数据 Excel、10-K 与 MD&A、官方历史、权威传记与长篇报道、当年电话会 | 当年研报对那次转折的评价 |
| 团队 | DEF 14A、近 12 个月 Form 4、CEO 发言与访谈、董事会公告 | — |
| 股价事件 | 日线（写明提供方）、当日公告或新闻 | 事件前后各 14 天研报 = 当时解读 |
| 历史估值 | 数据提供方（写明）或从财报自算 | 历史倍数图交叉验证 |
| 未来利好利空 | 最近两次电话会问答、10-K 风险因素、监管与诉讼文件 | 近 3 个月研报：每条谁支持、谁反对 |
| 行业与主题 | 行业协会与政府统计、龙头财报 | 行业 / 策略 / 主题 / 宏观类研报 |

- 富途是最新口径，要当年原报数字时从当年研报取并注明。
- 官方历史与研报说法明显不一致时才找第三方来源。

### 既有研究优先、少重复核对
1. 开工先读相关既有研究（路径由工单 A 列出），能用的记入阅读包"既有研究"一节；先找同一标的最新一次留档的复用部分。
2. 既有研究默认直接引用，来源清单记 Drive 路径、类型标"既有研究"。
3. 只有三种情况回原始出处查：① 数字过时，需更新到最新一季；② 和其他来源矛盾；③ 正文核心论点依赖的关键数字。回查后来源清单同时记既有研究路径和原始出处。
4. 新数据的出处要求不变。

## 流程

### D0 范围判定（不等用户）
1. 列映射表：公司 → 主行业（及次行业）→ 共同主题（没有写"无"）。
2. 判定写哪几层、各几篇；查既有研究与最新留档的结论卡，定哪些复用、哪些只做增量。
3. **只要主题或行业时**：只写对应层，写完直接交付；不建公司历史数据表，公司数字按"来源分工"取，已有历史数据表的直接引用；年化波动率、最大回撤由工单 A 用日线自算。
4. 一句话报告范围和产出，不等回复。
5. 派工单 A：写明对象与主行业、富途导出目录、任务文件夹、研报库位置、任务书第七节文献清单。等它的同时可以先读既有研究、写上层报告。

### D1 检索
- **工单 A 交回**：历史数据表与 png、`股价事件.csv`、`研报候选.csv`、`来源/`、`来源清单.csv`、`缺口.md`、既有研究路径。缺口影响核心论点的，在 `取舍.md` 写怎么处理。
- **研报**：从 `研报候选.csv` 挑要读的，一般 10–30 份。
- **文献检索**：任务书第七节"要读的角度"是起点。① 必读的全文由工单 A 取回，版本已注明。② 从必读往外找引用的、被引的、近年综述与反方研究，读摘要和相关章节，重要的升为通读。③ 任务书清单的作者、题目、年份写错的按原文更正，在角度清单注明。④ 任务书没列时自己按 ② 找。
- **公开资料**：工单 A 取了 10-K、DEF 14A、Form 4、电话会；官方历史、传记、长篇报道、访谈按"来源分工"自己找，每份在 `来源清单.csv` 登记 S 编号。
- **股价事件**：从事件前后 14 天的研报读出"当时解读"，填进 `股价事件.csv`。

### D2 阅读
- 阅读包用 `../templates/reading_pack.md`，加"既有研究"一节。出处台账用 `../templates/claim_ledger.csv`；历史节点、股价事件用 `templates/milestone_ledger.csv`、`templates/event_ledger.csv`，每行一个出处。
- **读账**：逐年读历史数据 Excel 写"财务时间线"（每年一行：营收与增速、利润率、资本开支、FCF、股数、净现金、当年大事）；每个历史节点在时间线上指出对应数字变化，对不上的写明为什么。
- **角度清单**：每份文献一行——作者、题目、年份、版本、读法（通读 / 摘要与相关章节 / 仅摘要）、来源（任务书列的 / 自己找的）、核心结论一句、与本报告的关系（支持、补充或冲突，指到章）。关系由读完的人写；与任务书框架冲突的单独标出。放这一篇的底稿。
- **数字台账（边写边记）**：`数字台账.csv`（`templates/trail_numbers.csv`），只记历史数据表之外的数，一行一个：来源编号与页码、Drive 路径或算式；"核心"列标核心论点依赖的；"位置"列写章节。历史数据表里的数不用记。

### D3 写作
- 外壳按 `templates/report_shell.md`；章节按任务书；多层时主题 → 行业 → 公司，每写完一层就交付那一层。
- 只写 `.md`；数字只取自历史数据表与数字台账；图直接插 `--png` 快照；要新画的图先写插图路径 `figN_<描述>.png`，并记进交接单"要新画的图"（图名、数据所在工作表与列、类型、图注结论句）。
- **写法硬要求**：
  1. 正文零出处标注：正文不出现 [R 编号]、[S 编号]、页码，也不出现"研报库""台账""对账""取证"这类过程用语。数据提供方可以写名字，如 WSTS、公司财报、某券商统计。
  2. 正文不写工作过程：取舍、数据缺口、修订说明、来源清单一律进底稿。
  3. 每个数字可追溯：在历史数据表里，或在数字台账里有一行。
  4. 图注为"图 N　结论句"；图给读者可比较的原始序列：同一窗口、同一口径的原始数据，不给加工过的三手结论图；正文要写"没有可靠对照"前先找对照。
  5. 写给冷读者：每份报告按"只拿到这一份文档的冷读者"来写：事实本身写清楚，读这一份就够。
- 图表见"图表"；写作补充规则见下；题型特有的写作顺序见题型模板"本题型加项"。

### D4 脚本检查
- `python3 scripts/check_numbers.py <报告>.md --xlsx <历史数据表或图表数据表> --ledger 数字台账.csv`：未命中的，写错就改正文，表外的数补台账，直到未命中为 0。
- 然后派工单 B；打回的只改打回单上的位置，改完 `check_numbers.py` 重跑。
- research-delivery 跑 `md2docx.py`、`check_delivery.py` 等格式脚本，内容类问题（报告外壳、出处标注、"图表优先"、缺图）写打回单，同样只改打回的位置。

脚本卡不到的规则（`standards/审稿清单.md` 未写脚本名的条目、题型模板"本题型加项"、任务书另定的章节与篇幅）写作时照做。做不对按 D7 记进 `LESSONS.md` 改 skill。内容由用户审。

### D5 交付
- 写 `交接单.md`（模板 `../research-delivery/交接单模板.md`），交给 research-delivery（工单 C）；它负责转换、排版、图表工作簿首页、上传、命名、补目录页码、交付核对与索引。
- **交付物清单**（每篇）：
  - 报告：Google 文档，外壳见 `templates/report_shell.md`。
  - 数据表：公司报告附历史数据表格（含"图表总览"与"股价统计"）；行业、主题报告有图表数据时附图表数据表格（结构见格式规范第 13.1 节，由 research-delivery 建）。
  - 图片：png，`figN_<描述>.png`，N 为图号。
  - 留痕：见"留档：复用与复核"。
  - 交付说明：结论、主要取舍、待核来源、任务书之外的重要文献与冲突研究（没有写"没有"），写在交接单里。

### D6 交叉审核
- 默认：`check_numbers.py` 未命中为 0 后做一次工单 B（低推理），查台账出处本身对不对。试用期前五篇在复核记录记"有误几处"，连续为零时由用户决定是否关掉。
- 复核记录出现"有误"或用户点名时，另开会话（不能是制作者会话）从留档复用部分找报告和表格，按工单 B 复核，追加到复核记录（`templates/trail_review.md`）。

### 模式 R：修订已交付的报告
本文件新增硬性要求或读者反馈问题时，逐篇做，一篇一张任务单：
1. 公司报告：先派工单 A 建历史数据 Excel。
2. 拿到老报告的 `.md`（没有的由 research-delivery 从 Google 文档导出），按现行外壳、写法硬要求、"写作补充规则"与图表规则逐条改内容，表外的数记进数字台账。必须保留修订痕迹时在交接单写明，由 research-delivery 在原文件上改。
3. 公司报告按题型模板补齐章节（财务全史、行业位置与竞争）与图表下限；只核台账标"核心"的数字，不符的改正并连同原值记入修订说明，其余注"非核心数字未复核"。
4. 修订说明写进底稿 `复核/修订说明_Vx.md`（位置 ｜ 原版 ｜ 修订 ｜ 结论是否改变）；版本号加一（`_V1.0` → `_V2.0`），旧版不删，文件另存由 research-delivery 做。
5. 行业、主题报告只做第 2 步，另把引用的公司数字与各公司 Excel 对一遍（`check_numbers.py` 加 `--xlsx`）。
6. V1.0 过程产物整理进新版留档的复用部分，写结论卡。
7. D4 重跑，交 research-delivery。

### D7 复盘
按 `../templates/retro.md` 与 `../LESSONS.md`：问题、根因、修改建议写入待处理区；用户确认后再改本文件。读者反馈的可通用规则同样走这里。

## 留档：复用与复核
| 部分 | 放什么 |
|---|---|
| 复用 | 历史数据表格；`来源清单.csv`；`数字台账.csv`（含"数据截至""核心""复核状态"列）；`研报摘要卡.csv`（R 编号为键）；`历史节点.csv`；`股价事件.csv`（含当时解读与 R 编号）；`结论卡.md`；`来源/`（原始来源副本，研报库已有的只记路径） |
| 复核 | `取舍.md`（决定 ｜ 选择 ｜ 理由，另列数据缺口）；`修订说明_Vx.md`（仅修订版）；`复核记录.md`（复核者追加） |

- 底稿必有件：`取舍.md`、`来源清单.csv`、`数字台账.csv`，修订版另有 `修订说明_Vx.md`；只放底稿，不进正文。上传与摆放由 research-delivery 做。
- 模板：`templates/trail_sources.csv`、`trail_numbers.csv`、`report_cards.csv`、`milestone_ledger.csv`、`event_ledger.csv`、`conclusion_card.md`、`trail_review.md`。
- 结论卡一页：数据截至；一句话结论；题型模板"读者要能回答的问题"各一句；最大的问题与判断；跟踪信号；与上一版相比改了什么。
- 复用：取最新一次留档的复用部分，先读结论卡；过时的只补截至日之后的新数据，补完整套写进本篇留档；已有 R 编号不重读 PDF；来源清单标"既有研究"；结论变了在结论卡与底稿写明改了什么、为什么。
- 复核：核心数字必须写到原始出处；复核按 D6，有误的按模式 R 处理，通过的下次标"已复核"。
- 留档只求差不多齐全，一次写成，之后只在复核记录追加；不删除、不覆盖、不打 zip。

## 默认口径（AI 自行套用，不询问）
| 事项 | 默认 | 可调整的情形（写进"取舍"） |
|---|---|---|
| 财务全史时间跨度 | 能多长就多长，1995 年前可省略；季度只取近 12 个季度 | 1995 年前有关键转折的放宽 |
| 超额收益基准 | SPY，科技股并列 QQQ | 没有大盘数据时用原始收益，标"超额收益待补" |
| 历史估值指标 | 近 10 年 P/E、EV/EBITDA、FCF 收益率 | 金融股 P/B + ROE；无利润 EV/Sales；REIT P/FFO |
| 时间口径 | 以报告日为准；财年与日历年差异在表头注明 | — |

## 图表
- **图表优先**（格式规范第 7 节 V01、V05）：走势、可比序列、阶段、先后、结构用图，正文只写关键节点数字与口径；按轮次组织的报告每个重要轮次一张"股价走势 + 阶段"图。research-delivery 打回的"图表优先"提示逐条改成图或删到关键节点。
- 题型模板里的图表数量是下限。
- 数据图的原生图在历史数据表格或图表数据表格的"图表总览"里（格式规范第 13.1 节，由 research-delivery 建）；报告插 `--png` 快照，图下写"数据与可编辑图表：<表格名> 图表总览第 X 图"。
- 自己定要画的只有行业份额变迁、同行横向比较、股价行为画像图；其余用快照，不重画。新画的图写进交接单，由 research-delivery 建图导出。

## 写作补充规则
- **数字必有口径**：每组重要数字正文至少一处写明经济含义、分子 ÷ 分母、样本、时间口径、单位，表头、脚注、括号不算；自建样本写出构成；同表口径变化逐行标注；表头写单位和时点，一张表一种口径；比例变化用"百分点"，金额变化用"%"。
- **括号**：正文不用括号补信息，单位、时间、口径、增速写进句子；英文简称直接并列（"晶圆代工设备 WFE"）；只有公式保留圆括号。
- **样式**：强调用加粗首句，不升级为标题。
- **输出风格**：与用户语言一致；金额、股数用万、亿；结论先行，短句。不构成投资建议；不臆测券商动机，提示其利益冲突。
- 表格版式、字体、颜色、命名、存储由 research-delivery 按 `standards/` 做，本技能不管。
