# 审稿清单

执行 AI 交稿前逐条自查，验收 AI 验收时用同一张清单复查；结果写进底稿"自检"的"审稿清单自查结果"一节（模板 `templates/trail_selfcheck.md`）。
本清单只查格式、追溯、交付合规、是否按任务书写，不查写得对不对。

- [ ] ① 第一章"一、结论与概述"有结论三样（判断、凭什么、什么信号说明判断错了）与概述两样（每章讲了什么、主要发现是什么）。
- [ ] ② 正文各章的章名、顺序与内容范围与任务书一致，外壳为标题 → 一、结论与概述 → 各章 → 附：口径与说明。
- [ ] ③ 正文 grep 出处标注（`[R`、`[S`、页码）与过程用语（研报库、台账、对账、取证）为零，`md2docx.py` 的"出处标注"一行为 0 处。
- [ ] ④ 正文每个数字在底稿 `数字台账.csv` 里有一行、"位置"列写了所在章节，脚本比对全部命中。
- [ ] ⑤ 图号按出现顺序、文件名 figN 与图号一致、图内无图号、图注为"图 N　结论句"、图下来源行无研报编号和页码。
- [ ] ⑥ `md2docx.py` 检查通过：报告外壳、出处标注、图下来源行、图号与文件名、标题编号均为 0 处，格式检查全部通过。
- [ ] ⑦ `check_delivery.py` 全部通过（不能运行时按 Drive 入口文件逐条人工核对）。
- [ ] ⑧ 取舍、数据缺口、修订说明、来源清单都在底稿，不在正文。
- [ ] ⑨ 通读一遍：不懂行的人能顺着正文读到结论，不需要翻底稿。
