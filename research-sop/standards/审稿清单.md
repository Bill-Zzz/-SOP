# 审稿清单（机械检查）

机械检查（格式、追溯、交付合规、是否按任务书写）由执行 AI 交稿前逐条自查（共 13 条；⑦、⑩、⑫、⑬ 为硬性，不通过不得交付），结果写进底稿"自检"的"审稿清单自查结果"一节（模板 `templates/trail_selfcheck.md`）；内容由用户自己审。
本清单不查写得对不对，不设 AI 内容验收；自检与交付说明里不得写成"内容已审"。

- [ ] ① 标题后有"一页摘要"（结论与主要内容的一页浓缩，不超过一页）；第一章"一、结论与概述"有结论三样（判断、凭什么、什么信号说明判断错了）与概述两样（每章讲了什么、主要发现是什么）。
- [ ] ② 正文各章的章名、顺序与内容范围与任务书一致，外壳为标题 → 一页摘要 → 目录 → 一、结论与概述 → 各章 → 附：口径与说明。
- [ ] ③ 正文 grep 出处标注（`[R`、`[S`、页码）与过程用语（研报库、台账、对账、取证）为零，`md2docx.py` 的"出处标注"一行为 0 处。
- [ ] ④ 正文每个数字在底稿 `数字台账.csv` 里有一行、"位置"列写了所在章节，脚本比对全部命中。
- [ ] ⑤ 图号按出现顺序、文件名 figN 与图号一致、图内无图号、图注为"图 N　结论句"、图下来源行无研报编号和页码；图给同一窗口、同一口径的原始序列，正文写"没有可靠对照"处写明了找过什么。
- [ ] ⑥ `md2docx.py` 检查通过：报告外壳、出处标注、图下来源行、图号与文件名、标题编号均为 0 处，格式检查全部通过；格式规范第 15 节其余项已逐项查，未通过或未核验的列明。
- [ ] ⑦ `check_delivery.py` 全部通过，含第 12 项"Google 文档目录：二级条目必须有页码"（硬性）：脚本读不到文档文本时，用 `--toc-evidence` 附人工确认（文档名｜二级目录带页码：是｜日期｜确认人），缺证据即不通过；目录页码按 `转换后修补清单.md` D1 补好之前，本条不得勾选。不能运行脚本时按 Drive 入口文件逐条人工核对，目录页码一项同样要附证据（导出 PDF 的目录页或截图），缺证据即不通过。
- [ ] ⑧ 取舍、数据缺口、修订说明、来源清单都在底稿，不在正文。
- [ ] ⑨ 按冷读者通读一遍（格式规范第 2 节写法硬要求 5）：只拿到这一份文档，每个事实都看得懂，能顺着读到结论。
- [ ] ⑩ **（硬性）重要轮次的"股价走势 + 阶段"图**（格式规范第 7 节 V05）：历史部分按轮次组织的报告，任务书列出的重要轮次——没列时为历史部分每一个完整轮次——每轮都有一张股价（或代表性指数）原始序列叠加该轮阶段起止的图；自检逐轮写"轮次 → 图号"。缺一即不通过，不得交付；只有该轮早于任何可得股价或指数序列、且自检写明找过的数据源与替代尝试时，才可列为例外。历史部分不按轮次组织的报告写"不适用"。
- [ ] ⑪ **（软性）图表优先提示已逐条处理**（格式规范第 7 节 V01–V04）：`md2docx.py`"图表优先"一行列出的数字密集段落、数值大表、没有图的正文章，每一条都有处理记录——改成了图、删到了关键节点，或在自检写明保留理由。提示本身不拦交付，但没有处理记录的不得勾选本条。
- [ ] ⑫ **（硬性）图表工作簿结构**（格式规范第 13.1 节 WB01–WB06）：报告有配套图表工作簿时——工作表用语义名，没有"图N数据"这类编号页名；第一张是"图表总览"，是集中报告全部重要数据图的原生图表看板，不是图号索引表；有来源页，语义页与图下来源行用到的来源 ID 都能在来源页找到；有"图表计算"放总览图的公式数据区；报告每张数据图都能追到一张语义页上的序列。自检逐图写"图号 → 总览第 N 张 → 语义页"，示意图、机制图这类没有数据序列的图写"不进总览"。`check_delivery.py` 第 13 项查页名、总览位置与原生图表、总览图引用、来源页与图表计算页；来源 ID 可追与逐图对应由执行 AI 人工查，缺一即不通过。年份筛选（WB04）是软性：自检写一行做了哪几张、不做的是固定窗口或单轮图。报告没有配套图表工作簿时写"不适用"。
- [ ] ⑬ **（硬性）首页按 Excel 规范第 5 节 E1–E12 自查**（`standards/Excel规范.md`）：报告有配套图表工作簿时，首页"图表总览"按 E1–E12 逐项自查并填自检表，硬项未过不得交付。报告没有配套图表工作簿时写"不适用"。
